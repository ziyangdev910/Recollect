## 2. 叙事主线

一句话：

> **不把学习搬进屏幕，而把屏幕藏到纸背后。**

五幕结构：

1. **Why**：纸笔仍然是最好的复习界面，但它不会计算。
2. **What**：学生缺的不是题，而是“下周该复习什么”的节奏。
3. **How**：手机负责调度、打印、回读；纸负责执行；人负责确认。
4. **Process**：规格先行、TDD、真机证据、AI 协作。
5. **Result**：一个从录入到再规划的完整闭环，以及一套可复现的工程方法。

### P03 创作理念

**核心结论**：纸是界面，手机是大脑，人做最后判断。

**页面文案**

- 大字：不把学习搬进屏幕，而把屏幕藏到纸背后。
- 纸是界面：保留纸笔的低干扰、可携带、可书写。
- 知识点是单元：题目只是载体，按掌握状态安排，而不是按题量。
- 人在环上：算法与 OCR 只给建议，最后一行由学生确认。
- 底部：端侧离线 · 无网络权限 · 数据留在本机。

**视觉与素材**

- 顶部一句大字；下方三栏卡片，每卡一个线性图标：纸 / 节点 / 对勾。
- 配色只用紫、墨、纸白。

**讲述重点**：纯 App 的问题是屏幕本身是干扰源；纯纸质的问题是纸不会计算。拾知站在中间。

### P04 问题与需求

**核心结论**：复习难，不难在“做题”，难在“安排”和“回写”。

**页面文案**

- 计划靠感觉：没有遗忘规律、没有每日容量，容易前松后紧。
- 纸面断链：今天做没做、掌握到什么程度，回不到下周计划。
- 屏幕干扰：长时间 App 学习分心、伤眼，难以坚持。
- 数据顾虑：云端上传、账号体系，对未成年人不友好。
- 底部：现有方案要么“全数字”，要么“全纸质”，缺一座桥。

**视觉与素材**

- 2×2 痛点卡片；右下角放一个“桥”的极简示意。
- 每张卡片只保留一句加粗短句 + 一行解释。
- **不要放没有出处的百分比。**

**讲述重点**：四个痛点，正好对应后面四个设计约束。

### P05 用户与场景

**核心结论**：目标用户是“习惯纸笔、需要周节奏”的初高中学生。

**页面文案**

- 主用户：初高中学生；有纸笔习惯；需要有人替他们“排节奏”；自控力一般。
- 典型一周：
  - 周日：录入本周题目与知识点。
  - 周日晚上：生成并打印 A4 周计划。
  - 周一到周日：每天按页填涂“掌握 / 较熟悉 / 不会”，写复习笔记。
  - 周末：拍照回读，逐行确认。
  - 下周一：系统按新状态生成下一周。
- 设计约束：单题 ≤ 4 个知识点；每日容量按分钟；冷却 7 天；一周一计划。

**视觉与素材**

- 横向 5 步用户旅程；每步配一个小图标，关键两步配手机截图。
- 素材：`evidence/screens/tag-25-entry-list-full.png`、`evidence/screens/printlabel-live-02-preview.png`

**讲述重点**：把“坚持”拆成一张纸和一次拍照，降低每周的启动成本。

### P08 技术架构

**核心结论**：分层架构让核心算法可单测、可替换，端侧完成全部推理。

**页面文案**

- 端侧推理：OCR、QR、OMR 全部在手机本地完成。

**视觉与素材**

### P09 核心算法：调度

**核心结论**：调度的是“知识点”，不是“题目”。

**页面文案**

- 四步流水线：
  - 候选：到期、未归档、未休眠。
  - 冷却：7 天内不重复安排。
  - 排序：最高档位 → 档位差 → 同档连续掌握度 → 目标日 → 题号。
  - 时间装箱：按每日可用分钟 first-fit，放不下就顺延记录。
- 记忆节奏：冷启动 1/3/7 天 → 有效反馈 ≥ 3 → DHP 简化模型（90% 保持率，30 天上限）。
- 特点：确定性、可复现、纯 Kotlin、属性测试。
- 底部：同一道题一周只打印一次。

**视觉与素材**

- 四段横向流水线；右侧一个小公式 `p(t) = 2^(-t/h)`；底部一条“确定性”标签。
- 不展开公式推导，只保留“遗忘曲线”意象。

**讲述重点**：不追求“AI 猜题”，追求“可解释的节奏”。

### P10 核心算法：打印与分页

**核心结论**：把计划变成一张“机器读得懂”的纸。

**页面文案**

- 按日强制分页，条目绝不跨页；放不下整条移到下页。
- 左 42% 填涂区：一知识点一行，三档 16:9 宽格。
- 右 58%：题目信息 + 复习笔记区。
- 每题一个 QR；四角 ArUco 定位；A4 / 300 DPI。
- 关键数字：内容区 26mm 起；填涂格 5.7×3.2mm；QR 18mm；页脚小字 pageId。

**视觉与素材**

- 打印稿大图居中；三个 callout 分别指向 ArUco、QR、填涂格；右侧列关键数字。
- 素材：`evidence/print/widebubble-2026-11-22-recollect-print-K7M2Q9-page-1.png`

**讲述重点**：纸不是截图，是一张有“坐标系统”的输入设备。

### P11 核心算法：回读与确认

**核心结论**：让纸“说话”，但最后由人签字。

**页面文案**

- 管线：CameraX / 相册 → ArUco 定位 → 透视矫正 2480×3508 → 逐题 QR → OMR 三档 → 中文 OCR → 人工确认。
- 判定：> 30% 命中；< 10% 未命中；10%–30% 模糊；唯一明确命中优先。
- 兜底：QR 失败可手动输入 pageId + 题号；重复页、未来日期、晚批次均有提示。
- 确认：逐行“接受 / 修改 / 本次未复习”，不能一键全部接受。

**视觉与素材**

- 上方 6 步管线；下方两张截图并排：扫描取景、确认页。
- 素材：`evidence/screens/scanB-03-camera-preview.png`、`evidence/screens/confirm-04-submitted.png`
- 用紫色标“机器”，墨色标“人”。

**讲述重点**：识别负责省力，确认负责可信；这也是产品与“全自动批改”的分界线。
