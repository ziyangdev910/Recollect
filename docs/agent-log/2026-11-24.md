## 追加：录入页键盘弹出后光标手柄停在旧位置（2026-11-24）

### 目标

用户反馈：部分页面文本框获得焦点、键盘弹出后，文本框被 `imePadding` 顶到键盘上方，但指示光标位置的小手柄（小水滴）停在文本框原来的位置，观感不佳。本轮修复该问题。

### 定位

- 真机（VKJ-AN00 / Android 16 / SDK 36）复现：`录入题目` 页滚到底部、聚焦「预估复习时长」后，输入框上移到键盘上方，手柄却停在键盘顶部（`dumpsys window` 中 Popup 窗口 `APPLICATION_SUB_PANEL` 固定在 `(145,1624)`，与输入框脱节）。
- 源码核对（Compose Foundation/UI 1.10.0）：光标/选区手柄是独立窗口里的 `Popup`，`AndroidPopup` 只在创建时通过锚点节点的 `onGloballyPositioned` 取一次 `parentBounds`；`verticalScroll` 滚动只平移内容、不重新测量/放置子节点，因此键盘引起的内部滚动不会触发重新锚定。`updateViewLayout` 只在光标位置变化时更新，且仍使用旧的锚点位置。
- 已验证无效的方案：手动调整页面宽度强制子树重新测量（Popup 锚点节点的约束不变，回调不派发）；`windowSoftInputMode=adjustPan`（窗口平移也不触发重新锚定，且整页上移、顶栏被顶出屏幕）。
- 结论：这是 Compose 手柄 Popup 的定位限制，应用层无法让既有 Popup 重新锚定；可靠修复是在键盘可见期间隐藏手柄。

### 改动

| 文件 | 意图 | 关联 |
|---|---|---|
| `feature/entry/.../QuestionEditScreen.kt` | 表单外层用 `CompositionLocalProvider` 在 `WindowInsets.isImeVisible` 为真时把 `LocalTextSelectionColors.handleColor` 置为透明；光标、选区高亮、输入与手柄拖动保持可用，键盘收起后手柄恢复显示并落在光标下方。标签管理对话框在 provider 之外，保持原样 | 2026-11-24 用户要求 |
| `CLAUDE.md` | 在 `:feature:entry` 描述中补充「键盘弹出期间隐藏 Compose 光标手柄」的实现约束 | — |
| `docs/changelog.md`、`docs/prompts.md`、本日志 | 记录本轮修复与验证 | — |

`docs/specs/` 无需变更：本轮只是 UI 层补偿 Compose 手柄 Popup 的定位限制，不涉及调度、数据模型或计划/打印规则。

### 验证

- `./gradlew :feature:entry:test verifyCorePurity` 通过；`:app:assembleRelease` 通过。
- 实体机 VKJ-AN00（release 正式签名覆盖安装，保留原数据）：
  - 修复前：聚焦底部输入框后手柄停在键盘顶部（`evidence/screens/ime-check-04-edit-focused.png`）；
  - 修复后：键盘展开期间不显示手柄（`ime-fix-01-focused.png`），收起键盘后手柄位于光标下方（`ime-fix-02-kb-hidden.png`）；

### 改动

| 文件 | 意图 | 关联 |
|---|---|---|
| `feature/planning/src/test/.../GeneratePlanUseCaseTest.kt` | 「容量不足」用例改为校验「缩短本题预估复习时长」「延长每日复习时长」「重新生成计划」三段建议，与 `PlanDeferredPreview.kt` 一致 | 2026-11-24 用户要求 |
| `app/.../AppRoot.kt` | 按路由切换窗口软输入 `adjust` 位：录入/编辑题目页为 `adjustResize`（禁止系统整窗平移，保留顶栏，由表单 `imePadding` 避让），其余页面恢复 `adjustPan`（系统默认，靠整窗平移把输入框带出）；只改 adjust 位并保留其他状态位，避免每次重组重复设置 | 2026-11-24 用户要求 |
| `CLAUDE.md`、`docs/changelog.md`、`docs/prompts.md`、本日志 | 记录本轮修复 | — |

### 定位

- 复现：录入页滚到底部、聚焦「预估复习时长」后，输入框下方出现约一屏高的白色区域，顶栏也被顶出屏幕。
- 真机排查：`dumpsys window` 显示应用窗口为 `adjust=pan`（系统把未声明的模式解析为 pan）；`uiautomator` 显示表单滚动视口被 `imePadding` 额外缩短。即系统整窗平移与 `imePadding` 同时生效，形成双重避让。
- 对照试验：显式 `adjustResize`（不作整窗平移）或去掉 `imePadding` 都能消除空白；前者保留顶栏、观感更好，故采用按路由设置 `adjustResize`。

### 验证

- `./gradlew test verifyCorePurity` 通过（计划模块失败已随断言同步修复）；`:app:assembleRelease` 通过。
- 实体机 VKJ-AN00（release 正式签名覆盖安装、保留数据）：
  - 修复前：输入框下方大块空白（`evidence/screens/ime-blank-01.png`）；
  - 修复后：顶栏保留、输入框紧贴键盘、无空白（`ime-blank-07-final.png`）；
  - 首页「每日复习时长」对话框仍正常显示手柄（`ime-blank-08-dialog.png`）；
  - `dumpsys window` 确认进入录入页 `adjust=resize`、返回首页恢复 `adjust=pan`。

### 未决 / 下轮建议

- 其余含底部输入框但未做 IME 避让的页面（确认页、扫描页手动输入）仍依赖系统整窗平移显示输入框，行为未变；若后续为它们补 `imePadding`，需要把窗口模式一并调整为 `adjustResize`，并按本页同样的方式处理光标手柄。
- 若后续统一改为「全应用边缘到边缘 + `imePadding`」的 IME 方案，可移除按路由切换软输入模式的逻辑。
