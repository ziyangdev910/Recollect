# 2026-11-22 代理日志：本周计划单例与打印快照保护（C-097）

## 目标

- 打印过本周计划后，再次点击首页“生成并打印本周计划”不得静默生成新计划号、覆盖 `Question.pageId/qrPayload`。
- 本周已有计划时复用同一 `planId`；只有用户显式“重新生成本周计划”并确认后才生成新计划，并把旧计划标记为已替代。
- 打印确认只为当前计划写快照；旧计划不得覆盖最新快照。

## 方案（用户批准）

schema v8 计划头 + `PlanSession` 复用/显式重新生成 + 打印快照写入守卫。

## 追加：填涂格改为答题卡式 16:9

### 目标与影响判断

- 把打印稿左侧 A/B/C 填涂格从 3.5mm 方框改为答题卡式 16:9 宽格（5.7 × 3.2mm），便于横向填涂。
- OMR 不读取方框外形，只采样每个框中心的 2.5mm×2.5mm 窗口；因此改外形本身不破坏识别。真正的风险是打印/扫描两端的列中心必须同步，否则 B/C 会错位。
- 项目尚未发布，不考虑旧模板/旧打印稿适配；打印与扫描统一从 `TemplateGeometry` 读取列中心，删除引擎内重复常量。

### 改动

| 文件 | 意图 |
|---|---|
| `core/pagination/TemplateGeometry.kt` | 新增列几何与填涂格参数；`bubbleLeftMm`/`bubbleCenterXMm`/`bubbleCentersXMm` 成为打印与扫描的唯一来源 |
| `feature/print/PrintLayout.kt`、`PrintRenderer.kt` | 按模板绘制 5.7×3.2mm 宽格；`BubbleLayout` 拆为宽/高 |
| `feature/scan/OpenCvScanEngine.kt` | OMR 直接用 `template.bubbleCenterXMm(column)` 计算中心；采样窗大小取模板参数 |

### 几何数值（a4Print）

- 列：序号 6mm → 间距 1.5mm → 知识点 34mm → 间距 1.5mm。
- 三格：宽 5.7mm、高 3.2mm、间距 1.55mm；左边界 69.0 / 76.25 / 83.5mm，中心 71.85 / 79.10 / 86.35mm；第三格右缘 89.2mm，与右侧信息区起点对齐。
- 行高仍为 7.5mm，分页输入未变；三格垂直居中（top = 行顶 + 2.15mm）。

## 追加：OMR 行判定误判修复（2026-11-22）

### 现象

- 使用 `evidence/print/fail_1.png`（603×862，计划 `GHB2EB` 第 1 页）扫描，确认页三行均为「无法识别」；纸面实际为 T-9=掌握、T-10=较熟悉、T-1=不会。

### 诊断

- 在真机用同一张图跑 `OpenCvScanEngine`（回归测试 `OmrFailImageRegressionTest`，按计划快照 33.0 / 107.5 / 182.0mm 取样）：
  - 四角 ArUco 正常，矫正后 2480×3508；
  - 三行暗像素比例分别为 `0.967/0/0`、`0/1/0`、`0/0/1`，本应全部 `OK`。
- 根因在行判定顺序：旧 `OmrClassifier.rowOf` 在“恰好 1 个命中”之前先判断“任一框 10%–30% 模糊 → 整行 `UNREADABLE`”。低分辨率整页图中，未填涂框的细边缘很容易让某个框落入 10%–30%，即使另一框已经明确 >30% 命中，整行仍被拖成「无法识别」。

### 修复

- `OmrClassifier.rowOf` 改为：
  1. >1 个明确 HIT → `CONFLICT`；
  2. 恰好 1 个明确 HIT → `OK`（其余框的 10%–30% 模糊读数不推翻唯一命中）；
  3. 0 个 HIT 且存在模糊框 → `UNREADABLE`；
  4. 0 个 HIT 且全部 MISS → `NO_MARK`。
- 单框阈值与 2.5mm 采样窗不变；`scan-pipeline.md`、`CLAUDE.md` D-09、`overview.md` 已同步。
