## 行为约定

- `PrintPlanInput` 与 `feature:planning.PrintJob` 分离：打印 feature 不依赖兄弟 feature；app 层负责 `notes → noteTexts` 映射。
- `PrintPlanViewModel` 只依赖 `PrintLauncher` 端口；`AndroidPrintLauncher` 持有 Context/PrintManager（R-03）。
- 计划成功生成时 `PlanPreviewViewModel` 把同一份 `PrintJob` 交给 `PrintPlanSession`；失败或空态清空，打印页不会再打印上一次的旧计划。
- 快照回写挂在 `PrintDocumentAdapter.onWrite` 成功之后；系统 API 没有实体打印完成的最终回调，因此“文档生成成功”即视为打印成功点。
- 打印页不重新分页、不压缩布局；系统打印预览直接消费 `PlannedPage`/`PlacedItem`（R-02）。

## 未决问题

1. **快照成功点**：以 `onWrite` 完成（打印文档生成）为准，不是实体纸张打印完成；用户取消打印对话框后仍可能已写快照。平台无最终回调，已登记 `docs/conflicts.md` C-094，等待人类选择 A（当前实现）/B（App 内确认后再写）。
2. **计划会话只存在内存**：`PrintPlanSession` 不持久化；进程重建后打印页显示“还没有可打印的计划”，需重新生成计划。
3. **PlanPreview 重新进入会重新生成计划**：从打印页返回计划预览会再次生成新计划并覆盖内存交接；打印旧稿后注意事项尚未在 UI 提示。
4. **首页“打印计划”入口**：无内存计划时进入打印页只会看到空态；后续可改为读取最近一份计划或隐藏入口。
5. **打印页只有摘要**：页内不展示 PDF 预览（由系统打印对话框提供）；未提供应用内“导出 PDF”按钮。
6. **打印服务不可用**只在 `PrintManager` 为空或调用抛错时提示；系统无打印机时由系统对话框处理。
7. R-01 仍未通过：本轮只验证了打印页与系统打印，不涉及真实打印稿回读识别精度。

## 下轮建议

- 明确并回写“打印成功”的判据（文档生成 vs 实体打印完成）；若需要更严格，考虑在系统打印回调/用户确认后再写快照。
- 把最新可打印计划持久化或在计划页复用同一 ViewModel，避免从打印页返回时重新生成计划。
- 评估首页打印入口的行为（读取最近计划或引导生成计划）。
- 继续 R-01：真实打印稿回读、OMR/QR 精度与 16KB 对齐。
